# Nightly run：把 Liar's Dice MLP 推向机器精度

> 目标：把 liars_dice1 的 MLP exploitability 推到机器精度（~1e-8）。
> 工作模式：自主夜间 run，先分析归因→提假设→设计实验验证。

## 1. 分析与归因：地板是一摞"盖子"的最大值

MLP 的 exploitability 地板 = **两个独立天花板的较大者**：

1. **表示天花板（representation）**：即便给 MLP *完美*训练信号，它能达到的最好 exploitability。
   有限宽 ReLU-MLP 无法精确表示 liars 的 Nash 混合策略（24576 信息态上的不规则 bluff
   频率，含无理比例）。残差逼近误差设了一个硬下限。**若这个下限是 ~1e-3，则任何算法**
   （RL 或别的）**都到不了机器精度**——目标不可达，诚实结论是"表示受限"。
2. **算法天花板（algorithm）**：ACH 训练动力学叠在上面的部分——噪声评论家
   （explained_variance ~0.15 → 优势符号错）、门控封顶、1/π_old（已部分修）、熵偏置。
   本会话已把这部分从 0.205 剥到 avg 0.147（iw_clip=20 + cap256）。

当前状态（avg exploitability，seed 0）：
- baseline l_th=2 noclip cap128: **0.184**
- + iw_clip=20（B1）: 0.163（4-seed）
- + cap256（B5）: **0.147**

距机器精度（~1e-8）还有 ~7 个数量级。

## 2. 核心假设

**机器精度对 MLP 而言由"表示"而非"算法"封顶。**

理由：24576 信息态 vs 一个 ~10⁴ 参数的 MLP——MLP 必须跨信息态压缩泛化；Nash 策略的
细粒度混合比例（精确阈值 bluff 频率）很难被 ReLU-MLP 精确表示。即便把算法天花板降到 0
（完美优势 + 无门控 + 无熵），表示天花板仍会卡住。

## 3. 决定性实验：把精确 Nash 蒸馏进 MLP

**测表示天花板**：用 tabular CFR+ 解 liars 的精确 Nash（exploitability ~1e-8），再做
**监督蒸馏**——用 KL(MLP || Nash) 把 Nash 策略直接拟合进 MLP（不经过 RL/评论家/门控）。
蒸馏后 MLP 的 exploitability **就是表示天花板**（与算法无关）。

- 若蒸馏 MLP ~1e-3 → **表示受限**：MLP 到不了机器精度，目标不可达。诚实结论 + 给宽度/
  深度 sweep 的表示下限。
- 若蒸馏 MLP ~1e-6+ → **算法受限**：表示够用，去剥算法天花板（B3 oracle 优势 + 门控/熵/
  lr 削减），把 RL 推到表示下限。

这是 keystone：低成本（监督训练，几分钟一轮宽度 sweep）、低风险（不动核心训练循环）、
决定后续整条路径。

## 4. 后续（按蒸馏结果分支）

- **表示受限**：宽度/深度 sweep（{128,256,512,1024,2048}、{256,256}）找表示下限；报告
  "MLP 最低 X，受表示限制；机器精度需 tabular（仓库已有 CFR+）"。
- **算法受限**：实现 B3（seqform 精确优势替代 GAE，绕过噪声评论家）+ 削盖子（iw_clip +
  抬 l_th + β→0 + lr 退火 + 大 batch），把 RL 推向表示下限。

## 5. 实验日志

### 5.1 蒸馏初探（决定性）

把 CFR+ Nash（150 iter，exploitability 2.2e-3）监督蒸馏进 MLP（KL/NLL 拟合），宽度 sweep
（3001 epoch，固定 lr=1e-2）：

| width | final NLL | distilled expl |
|---|---|---|
| 256 | 0.296 | 0.108 |
| **512** | 0.293 | **0.083** |
| 1024 | 0.323 | 0.089 |
| 2048 | 0.305 | 0.108 |

**三个关键发现（修正了 §2 的初步假设）：**

1. **Nash 自熵 H(Nash) = 0.268 nats/infoset**（Nash 多数信息态近乎确定性，只在阈值点混合）。
   蒸馏 NLL 停在 ~0.30 ≈ H(Nash) + 残差 → **MLP 其实把 Nash 拟合得很好**（残差 KL ≈ 0.03 nats）。
   NLL 平台不是表示失败，是 H(Nash) 的不可约下限。
2. **exploitability 对小策略偏差超敏感**：KL 0.03 → expl 0.083，比值 ~2.6×。即
   **expl ≈ 2.6 × KL(Nash‖MLP)**——把 KL 压下去就直接把 expl 压下去。到机器精度（1e-8）需
   KL ~4e-9（float32 MLP 在 ~1e-7 处也有硬底）。
3. **蒸馏（0.083）已低于 RL 地板（0.147）** → MLP 能表示比 RL 达到的更好的策略；RL 算法在
   "留下" ~0.06。且蒸馏是**最小化 KL 的最直接手段**（RL 是间接的）——蒸馏既是测量工具，
   也可能是逼近低 exploitability 的**解法本身**。

### 5.2 NLL/KL 平台是优化还是表示？

宽度 sweep（固定 lr）NLL 在 256–2048 全程 ~0.30（宽度无关）→ 怀疑是**优化**（固定 lr 没收敛），
不是容量。**退火 lr（cosine→0，10000 epoch）证实：KL 0.03→0.012，expl 约减半，且更宽单调改善**
（固定 lr 的 U 形是优化伪影）：

| width | 固定 lr expl | 退火 expl | 退火 KL |
|---|---|---|---|
| 256 | 0.108 | 0.057 | ~0.016 |
| 512 | 0.083 | 0.051 | ~0.013 |
| 1024 | 0.089 | **0.041** | ~0.012 |

→ KL 平台**部分是优化**（退火破开）。exploitability 0.041（width 1024）已远低于 RL 地板 0.147。
路径明确：**把蒸馏的 KL 一路压下去**（更低 final lr、更多 epoch、更宽），expl 按 ~3.4×KL 比例下降。
float32 MLP 的硬底 ~KL 1e-7（expl ~3e-7）；要更低保机器精度需 float64 MLP。
