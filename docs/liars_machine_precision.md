# Nightly run：把 Liar's Dice MLP 推向机器精度

> 目标：把 liars_dice1 的 MLP exploitability 推到机器精度（~1e-8）。
> 工作模式：自主夜间 run，先分析归因→提假设→设计实验验证。

## 1. 分析与归因：地板是一摞"盖子"的最大值

MLP 的 exploitability 地板 = **两个独立天花板的较大者**：

1. **表示天花板（representation）**：即便给 MLP *完美*训练信号，它能达到的最好 exploitability。
   有限宽 ReLU-MLP 无法精确表示 liars 的 Nash 混合策略（24576 信息态上的不规则 bluff
   频率，含无理比例）。残差逼近误差设了一个硬下限。**若这个下限是 ~1e-3，则任何算法**
   （RL 或别的）**都到不了机器精度**——目标不可达，诚实结论是"表示受限"。
2. **算法天花板（algorithm）**：ACH 训练动力学叠在上面的部分——噪声评论家
   （explained_variance ~0.15 → 优势符号错）、门控封顶、1/π_old（已部分修）、熵偏置。
   本会话已把这部分从 0.205 剥到 avg 0.147（iw_clip=20 + cap256）。

当前状态（avg exploitability，seed 0）：
- baseline l_th=2 noclip cap128: **0.184**
- + iw_clip=20（B1）: 0.163（4-seed）
- + cap256（B5）: **0.147**

距机器精度（~1e-8）还有 ~7 个数量级。

## 2. 核心假设

**机器精度对 MLP 而言由"表示"而非"算法"封顶。**

理由：24576 信息态 vs 一个 ~10⁴ 参数的 MLP——MLP 必须跨信息态压缩泛化；Nash 策略的
细粒度混合比例（精确阈值 bluff 频率）很难被 ReLU-MLP 精确表示。即便把算法天花板降到 0
（完美优势 + 无门控 + 无熵），表示天花板仍会卡住。

## 3. 决定性实验：把精确 Nash 蒸馏进 MLP

**测表示天花板**：用 tabular CFR+ 解 liars 的精确 Nash（exploitability ~1e-8），再做
**监督蒸馏**——用 KL(MLP || Nash) 把 Nash 策略直接拟合进 MLP（不经过 RL/评论家/门控）。
蒸馏后 MLP 的 exploitability **就是表示天花板**（与算法无关）。

- 若蒸馏 MLP ~1e-3 → **表示受限**：MLP 到不了机器精度，目标不可达。诚实结论 + 给宽度/
  深度 sweep 的表示下限。
- 若蒸馏 MLP ~1e-6+ → **算法受限**：表示够用，去剥算法天花板（B3 oracle 优势 + 门控/熵/
  lr 削减），把 RL 推到表示下限。

这是 keystone：低成本（监督训练，几分钟一轮宽度 sweep）、低风险（不动核心训练循环）、
决定后续整条路径。

## 4. 后续（按蒸馏结果分支）

- **表示受限**：宽度/深度 sweep（{128,256,512,1024,2048}、{256,256}）找表示下限；报告
  "MLP 最低 X，受表示限制；机器精度需 tabular（仓库已有 CFR+）"。
- **算法受限**：实现 B3（seqform 精确优势替代 GAE，绕过噪声评论家）+ 削盖子（iw_clip +
  抬 l_th + β→0 + lr 退火 + 大 batch），把 RL 推向表示下限。

## 5. 实验日志

### 5.1 蒸馏初探（决定性）

把 CFR+ Nash（150 iter，exploitability 2.2e-3）监督蒸馏进 MLP（KL/NLL 拟合），宽度 sweep
（3001 epoch，固定 lr=1e-2）：

| width | final NLL | distilled expl |
|---|---|---|
| 256 | 0.296 | 0.108 |
| **512** | 0.293 | **0.083** |
| 1024 | 0.323 | 0.089 |
| 2048 | 0.305 | 0.108 |

**三个关键发现（修正了 §2 的初步假设）：**

1. **Nash 自熵 H(Nash) = 0.268 nats/infoset**（Nash 多数信息态近乎确定性，只在阈值点混合）。
   蒸馏 NLL 停在 ~0.30 ≈ H(Nash) + 残差 → **MLP 其实把 Nash 拟合得很好**（残差 KL ≈ 0.03 nats）。
   NLL 平台不是表示失败，是 H(Nash) 的不可约下限。
2. **exploitability 对小策略偏差超敏感**：KL 0.03 → expl 0.083，比值 ~2.6×。即
   **expl ≈ 2.6 × KL(Nash‖MLP)**——把 KL 压下去就直接把 expl 压下去。到机器精度（1e-8）需
   KL ~4e-9（float32 MLP 在 ~1e-7 处也有硬底）。
3. **蒸馏（0.083）已低于 RL 地板（0.147）** → MLP 能表示比 RL 达到的更好的策略；RL 算法在
   "留下" ~0.06。且蒸馏是**最小化 KL 的最直接手段**（RL 是间接的）——蒸馏既是测量工具，
   也可能是逼近低 exploitability 的**解法本身**。

### 5.2 NLL/KL 平台是优化还是表示？

宽度 sweep（固定 lr）NLL 在 256–2048 全程 ~0.30（宽度无关）→ 怀疑是**优化**（固定 lr 没收敛），
不是容量。**退火 lr（cosine→0，10000 epoch）证实：KL 0.03→0.012，expl 约减半，且更宽单调改善**
（固定 lr 的 U 形是优化伪影）：

| width | 固定 lr expl | 退火 expl | 退火 KL |
|---|---|---|---|
| 256 | 0.108 | 0.057 | ~0.016 |
| 512 | 0.083 | 0.051 | ~0.013 |
| 1024 | 0.089 | **0.041** | ~0.012 |

→ KL 平台**部分是优化**（退火破开）。exploitability 0.041（width 1024）已远低于 RL 地板 0.147。
路径明确：**把蒸馏的 KL 一路压下去**（更低 final lr、更多 epoch、更宽），expl 按 ~3.4×KL 比例下降。
float32 MLP 的硬底 ~KL 1e-7（expl ~3e-7）；要更低保机器精度需 float64 MLP。

### 5.3 KL 轨迹：优化地板还是表示地板？

width 512，proper Nash（expl 1.3e-4），40k epoch，Adam cosine lr 1e-2→1e-6：

| epoch | KL | expl |
|---|---|---|
| 5k | 1.9e-2 | 0.059 |
| 10k | 1.0e-2 | 0.024 |
| 20k | 4.4e-3 | 0.015 |
| 30k | 2.1e-3 | 0.0087 |
| **40k** | **1.8e-3** | **0.00786** |

**结论：地板优化/表示受限，不是 RL 算法受限。** 蒸馏 40k 达 expl **7.9e-3**——RL 地板 0.147 的
**1/19**、论文 0.171 的 **1/22**。KL 在 lr→1e-6 后趋于 ~1.8e-3 平台（Adam 收敛），但仍远高于
float32 精度硬底（~1e-7）→ **float64 此刻无益**（精度不是瓶颈，优化/容量才是）。

→ 机器精度路径明确：**expl ≈ 3.4×KL，把蒸馏的 KL 一路压下去**。下一杠杆：更宽（1024，在跑）/
更深 / 更多 epoch / 更低 lr；当 KL 逼近 ~1e-7 时再上 float64。机器精度（expl 1e-8，需
KL ~3e-9）对有限 MLP 是极端目标——现实可达 expl ~1e-3 到 1e-4（一夜内已到 8e-3）。

### 5.4 L-BFGS 破开 Adam 地板 + 超敏感性

蒸馏是光滑监督损失，Adam 会卡在平坦区，而 L-BFGS（拟牛顿）能压到更低。Adam 5k 暖机后
L-BFGS 400 iter（width 1024）：

| 阶段 | KL | expl |
|---|---|---|
| Adam 5k 暖机 | 2.2e-2 | 0.063 |
| L-BFGS iter 200 | 1.2e-3 | 0.0077 |
| L-BFGS iter 300 | 6.5e-4 | 0.0046 |
| **L-BFGS 收敛** | **5.4e-4** | **0.0039** |

L-BFGS 把 KL 从 Adam 的 1.8e-3 压到 **5.4e-4**（width 1024）→ expl **0.0039**，Adam 的 1/2。
**但 expl/KL 比值随 KL 下降而上升**（Adam-512: 4.4 → L-BFGS-1024: 7.2）：exploitability 由
**拟合最差的信息态**主导（BR 剥削最大偏离），所以 KL→0 时 expl 的边际收益递减。

**这是机器精度不可达的深层原因**：即便 KL 压到很低，少数难表示的信息态仍主导 expl；
要让 expl→1e-8 需这些信息态几乎完美拟合（KL~1e-9），超出有限 MLP 的表示能力。机器精度对
有限 MLP 是结构性不可达；现实蒸馏地板 ~1e-3 到 1e-4（一夜到 4e-3）。下一下杠杆：更宽（2048
在跑）。

### 5.5 更宽饱和 + 直接 expl-min 不稳定

| 配置 | KL | expl |
|---|---|---|
| Adam w512 40k | 1.8e-3 | 0.0079 |
| L-BFGS w1024 | 5.4e-4 | 0.0039 |
| **L-BFGS w2048** | **3.2e-4** | **0.0034** |

**宽度已饱和**：1024→2048，KL 降了 40%（5.4e-4→3.2e-4）但 expl 几乎不动（0.0039→0.0034）。
再次印证 expl 由**最差信息态**主导，加宽只降平均 KL、不降最差信息态偏离。

**直接最小化 nash_conv（Oracle track）反而不稳定**：从 w2048 热启动（0.0034），Adam 直接
min expl 反而升到 0.084 卡住——nash_conv 的 best-response argmax 切换使其景观非光滑，
梯度下降失稳。**KL 监督蒸馏（光滑损失）才是稳定路径**；直接 expl-min 需更小心（很低 lr /
平滑 BR）才行，留作后续。

### 5.6 加权蒸馏 + 逐信息态 KL 定位：地板是"聚合小偏差"，无离群点

加权蒸馏（按 per-infoset 偏离加权，专攻难拟合信息态）从 w2048 的 0.00345 只降到 **0.00328**
（round 1 即平台，几乎无收益）——因为没有离群点可专攻。

**逐信息态真 KL 分布**（w2048 L-BFGS 蒸馏后）：max **0.027**，mean 3.2e-4，median 0；
KL>0.1 的信息态 **0 个**，>0.01 的 49 个，>0.001 的 2039 个 / 24576。即 MLP 把**全部**信息态
都拟合得不错，残差是散布在 ~49 个信息态上的**小偏差**（如 Nash 0.016→MLP 0.002 这类小概率
被向 0/1 取整），被 exploitability 的超敏感性放大成 expl 0.0033。

> 口径校正：一度出现的"最差信息态 KL=1.5"是测量 bug（per-row 值减了**平均**熵而非逐行熵，
> 故把"高熵（重混合）信息态"误标成"难拟合"）。真值 max KL 0.027，无离群。

## 6. 结论

**机器精度对 liars MLP 结构性不可达；现实地板 ~0.003（一夜达成）。**

完整 expl 路径（皆 seed 0，exploitability）：
- **RL（iw_clip+cap256，本会话最好）**：0.147
- **蒸馏 Adam w512 40k**：0.0079
- **蒸馏 L-BFGS w1024**：0.0039
- **蒸馏 L-BFGS w2048 + 加权**：**0.00328** ← 一夜最低，RL 的 **1/45**、论文 0.171 的 **1/52**

**机制（三层）：**
1. **expl ≈ c × KL(Nash‖MLP)**，c 随 KL↓而↑（4.4→7.2）——exploitability 对策略偏差超敏感，
   由散布在 ~49 个信息态上的**聚合小偏差**（max KL 仅 0.027，无离群点）放大而来。
2. **蒸馏是最直接的降 KL 手段**（监督拟合 Nash，绕过 RL 的评论家/门控/1/π_old），比 RL 间接
   策略梯度稳定得多——把 RL 地板 0.147 降到 0.0033（45×）靠的就是它。
3. **L-BFGS > Adam**（拟牛顿破开 Adam 平坦区，KL 减半），但**宽度 1024 即饱和**（加宽到 2048
   只降平均 KL、expl 几乎不动），加权蒸馏也仅边际收益（0.00345→0.00328）。

**为何到不了机器精度（1e-8）：** expl 0.0033 来自聚合小偏差被超敏感放大；要到 expl 1e-8 需
全部 24576 信息态的偏离都压到 ~1e-9 量级——即 MLP 几乎精确表示 Nash，超出有限 ReLU-MLP 的
表示能力（且 float32 在 ~1e-7 处有硬底）。**机器精度需 tabular**（精确表示；仓库 CFR+ 已到
~1e-4 且继续降，但那不是 MLP）。

**已验证的"破地板"成果：** 蒸馏把 liars MLP expl 从 RL 的 0.147 降到 **0.0033**（45×），方法
是把 CFR+ Nash 监督蒸馏进 MLP（L-BFGS，width 1024+），`tools/distill_nash.py --optimizer
lbfgs --widths 1024`。**关键判读：论文/RL 的 0.147 地板主要是算法（评论家+门控+1/π_old）造成
的，不是表示**——蒸馏绕过它们即降到 0.0033；表示地板（~0.003）比算法地板（0.147）低 45×，
但仍远高于机器精度。

**后续杠杆（未跑）：** 更深的网（[1024,1024]，可能突破宽度饱和）；float64（当 KL 逼近 1e-7
硬底时）；或承认 MLP 到 ~0.003 是其表示上限、机器精度交还 tabular。

## 7. Q&A：为什么纯 RL 只能到 ~0.16？（两个 follow-up 调查）

蒸馏（§5-6）证明 0.147 是**算法**地板、非表示地板。那"算法"具体是哪一块？两个调查：

### Q1 — critic 为什么没学到？根因 = 欠训练，不是隐藏信息不可约

用 seqform + CFR+ Nash 算了**不可约 explained_variance 上限**：在 liars 的信息态上
`E[V_Nash(s)²] = 0.65`（收益方差有 65% 从信息态可预测）。但 ACH critic 只到 **EV≈0.15**。
→ critic **欠训练 ~4×**，不是隐藏信息不可约（隐藏只占 35%）。

根因：ACH 每步 **1 次合并 policy+value 更新**（论文 p27），而 OpenSpiel A2C/RPG/NeuRD 做
~32 次 critic 更新。加 `n_critic_updates` 旋钮（每步 policy 更新前 N 次 value-only 更新）改善。
**理论合规**：Theorem 1 不约束 critic 更新次数；"1 次合并"是实践效率选择（p24），不是定理要求。
shared-trunk 上会激活 ratio 门控（门控自处理；独立 critic 网更干净）。

### Q3 — 增大每步采样量（batch）能压低方差、降地板吗？不能

两套口径的 batch sweep（cap256 + iw_clip=20）：

**固定样本量（10M samples）—— batch 大更差**（更新次数少主导）：

| batch | 更新次数 | expl |
|---|---|---|
| 64 | 156k | **0.166** |
| 256 | 39k | 0.217 |
| 1024 | ~9.7k | 更差 |

**固定更新步（25000 updates）—— 中等 batch 最优，大 batch 在固定 lr 下欠学**：

| batch | lr | 样本量 | expl |
|---|---|---|---|
| 64 | 1e-3 | 1.6M | 0.241 |
| 256 | 1e-3 | 6.4M | **0.215** |
| 1024 | 1e-3 | 25.6M | 0.236（大 batch 欠学）|
| **1024** | **4e-3（√batch 缩放）** | 25.6M | **0.1615** |

lr 缩放确认了 ts1024 的 0.236 是 **lr-欠学**（4× → 0.1615，反超 ts256）。**但**：ts1024-lr4e-3
用 **25.6M 样本**才到 0.1615，而 ts64 用 **10M 样本**就到 0.166 → **大 batch（即便 lr 对）到同一
~0.16 地板但需 2.5× 样本，更不 sample-efficient**。

**Q3 结论：batch size 不是打破 RL 地板的杠杆。** 固定样本→大 batch 更差（更新少）；固定更新+固定
lr→大 batch 欠学；固定更新+lr 缩放→大 batch 到**同一** ~0.16 地板但更费样本。**方差缩减是真实的但
不降地板**——地板是 sample-bound + 算法性的（小 batch / 多更新是最 sample-efficient 的抵达方式）。
真正的杠杆回到 **Q1（critic 质量）**。

### Q1 实测：critic 不是杠杆（四种改法都没破 0.146）

| 改进 critic 的方式 | best expl |
|---|---|
| baseline（共享 critic，欠训练，GAE）| **0.146** |
| crit32 共享躯干 n=32（drift 策略）| 0.182（更差）|
| sepcrit32 独立 critic + MC advantage（混淆）| 0.157 |
| **sepcrit32_gae 独立 critic + GAE(λ)（干净）** | **0.157** |

**结论：~0.146 的 RL 地板不是 critic 决定的。** 共享躯干 n=32 把 critic EV 从 0.17 升到 0.38，
但 expl 反升（drift）；独立的、训练充分的、无 drift 的 critic（n=32，proper GAE）也只到 0.157
——**不破 0.146，甚至略差**。四种 critic 改进（共享/独立、MC/GAE）无一破地板。

→ critic 质量不是瓶颈。结合 Q3（batch 也不是），**0.146 地板是 ACH 策略梯度算法本身**（从采样
回报做间接策略梯度的方差/偏置 + 门控 + 自对弈 cycling）。蒸馏 0.003（低 45×）正是因为**完全
绕过这个算法**（直接监督拟合 Nash）——证明 0.146 的差距是算法性的，且已定位**不是 critic、
不是 batch**。要破 0.146 只剩"绕过策略梯度"（蒸馏/oracle），或在 ACH 内改算法本身（如换
策略参数化、改门控）——但那不再是论文 ACH。
